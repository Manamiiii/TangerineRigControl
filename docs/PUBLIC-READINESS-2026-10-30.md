## 1. 定位、用户与成熟度

TangerineRigControl 将多套原厂软件的常用灯光、屏幕开关集中到 Windows 控制台、托盘和全局快捷键。实际价值是减少日常重复操作，不是提高硬件兼容性或替代原厂软件。

最适合已经使用 L-Connect 3、KANALI、iGC.Lite 或华硕 Aura，愿意完成一次录制校准的中文 Windows 用户。只需要其中一部分设备也能使用。期待自动识别任意硬件、零配置或在任意页面可靠切换状态的用户不适合当前版本。

最值得介绍的三个价值：

1. 一处发起多个设备的日常开关，减少来回寻找原厂窗口。
2. 托盘、全局快捷键和停止入口适合重复使用，结果逐项可查看。
3. 配置留在本机，有草稿、备份与恢复保护；不需要账户或云服务。

功能实现情况：

| 范围 | 实际实现与证据 | 成熟度判断 |
| --- | --- | --- |
| 坐标录制与回放 | F8 记录客户区相对坐标；点击前校验窗口、进程、权限、前台及遮挡 | 核心链路完整；起始页面、尺寸与重复开关效果依赖用户校准 |
| 配置 | XML、旧字段兼容、草稿、备份、损坏保护、外部修改及新版本保护 | 已有隔离自检；本轮继续通过，不改变格式 |
| 托盘、快捷键、批量操作 | 顺序执行，单项错误通常继续，支持协作式取消 | 代码完整；本轮改善取消结果保留，未操作实际快捷键和设备 |
| 窗口恢复 | L-Connect 本机命名管道，KANALI 现有实例重开，iGC 启动器匹配 | 特定软件适配，不是通用窗口自动化保证 |
| Aura | COM 线程所有权、分类写黑、释放控制、15 秒等待、退出限时释放 | 实现完整，但硬件效果和持续争用缺少本轮验收；超时无法中断 COM |
| 分发 | Windows CI 构建与自检；本轮增加白名单打包及校验信息 | 可准备预览分发；尚无 Release、未选择许可证、未代码签名 |

结论：已经超出纯技术实验，适合发展为面向特定硬件用户的小型公开工具；目前仍有明显个人设备适配边界。先完成许可证和当前版本实机验收，再小范围邀请相同硬件用户试用。暂不适合宣传“通用 RGB 工具”“开箱即用”“全设备稳定兼容”。

## 3. 安全、隐私与依赖检查

- 阅读当前全部被跟踪的代码、项目配置、CI、文档及图标生成脚本；图标为仓库脚本生成的资源。忽略目录中的历史程序、真实配置、实验截图不作为待发布内容。
- 检查本地全部 6 个可达提交的文件清单与常见密钥、私钥、凭据、个人用户路径模式，未发现命中。未证明不存在其他格式的秘密，也未重写历史。
- 当前控制程序没有 HTTP 客户端、服务器、账户、遥测或上传链路。唯一 IPC 为本机原厂窗口唤醒，校验服务端进程并使用匿名模拟级别，不作为硬件控制通道。
- manifest 使用 `asInvoker`；HKCU Run 不自动提权。没有新增管理员计划任务、系统服务或全局策略。
- XML 禁止 DTD/外部解析器，限制坐标、步数和等待时间；配置通过临时文件替换，保留有效备份并阻止已知外部修改。未修改现有恢复逻辑。
- 启动入口由用户选择，仍属于需要信任的本机程序；扩展名校验不是二进制真实性认证，也不使他人的配置变得可安全导入。
- 项目引用是 .NET Framework 系统程序集与自写 Aura COM 接口定义，没有 NuGet 运行依赖或捆绑厂商 DLL。本轮未新增第三方依赖。厂商组件的许可与兼容性不能由本仓库替其承诺。
- 没有 LICENSE 是发布前的授权决策，不能由助手擅自改成 MIT 或其他许可；README 现在明确状态。公开仓库不等于已完成开源授权，参阅 [GitHub 官方说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。

## 8. 新用户验收与后续顺序

新用户应能按 README 完成：确认适用设备 → 准备运行环境和原厂软件 → 下载、校验、解压 → 配置一个设备 → F8 录制开关 → 按需调整等待 → 两次保存 → 单项和重复开关验证 → 再启用全部操作和登录启动。

必要人工验收只包括无法由本轮隔离测试证明的内容：原厂页面可恢复、点击落点正确、设备开关与重复操作符合预期、SDK 关闭保持和退出后默认灯效符合说明。配置损坏、等待编辑取消、旧字段保留和超时替身测试已由助手完成，不要求用户破坏真实配置。

后续按收益/投入排序，最多五项：

1. 确定许可证并补齐 LICENSE，解除公开授权不清的障碍。
2. 对当前四组功能完成一次真实设备验收，记录型号、软件版本及未通过项。
3. 经另行授权，推送后确认标准 CI，再发布一个带说明和校验值的预览包；填写 Description/Topics。
4. 邀请少量相同硬件用户按首次使用步骤试用，用具体失败记录决定后续适配。
5. 根据实际问题优先补 DPI/窗口尺寸提示或特定版本适配；只有 SDK 挂起成为真实痛点时再考虑进程隔离。

这些是建议，未开始推送、发布或招募用户。
