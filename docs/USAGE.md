# 使用与排错指南

面向第一次使用 TangerineRigControl 的用户。下载入口与运行环境见 [README](../README.md)。当前为预览版本；请先确认自己的设备能在原厂软件中正常开关。

## 下载校验

从仓库的 main 分支成功构建下载；GitHub Actions 会把构建产物包装为外层 ZIP。本轮打包流程生成的内层文件为 `TangerineRigControl-<版本>-windows-portable.zip` 及同名 `.sha256`。

把两者解压到同一目录，在 PowerShell 执行（将文件名替换为实际下载版本）：

```powershell
Get-FileHash .\TangerineRigControl-0.3.1-preview-windows-portable.zip -Algorithm SHA256
Get-Content .\TangerineRigControl-0.3.1-preview-windows-portable.zip.sha256
```

两处哈希应一致。它用于核对下载完整性，不是代码签名或安全保证。旧产物可能没有校验文件，不应伪造一个校验值来“验证”它。

解压内层 ZIP 后，`BUILD-INFO.txt` 提供版本和源码标识，`SHA256SUMS.txt` 提供 EXE 的哈希。本地尚未提交的构建会标明工作树有修改，不能作为干净提交的发布证明。

## 先完成一个设备

1. 运行 EXE，进入“设置与录制”。不要急于启用登录启动或点击“全部”。
2. 选择需要的设备标签页，用“浏览…”选择已安装的原厂 `.exe`，不要选择卸载器、快捷方式、脚本或来源不明的程序。自动发现的路径也需要用“打开原厂软件”核对。
3. 不需要的设备可保持空白。若不使用华硕 SDK，取消顶部 SDK 选项。空录制会在全部操作时被跳过；已选用 SDK 的华硕组仍会尝试 SDK 操作。
4. 按下方步骤配置一项，保存后返回主界面，先验证该项，再逐步加入其他设备。

主界面的“原厂软件”打开对应原厂窗口；“设置与录制”编辑本工具配置。华硕 SDK 模式通常无需配置原厂 EXE；该行“原厂软件”仍需要单独的可用入口才能打开窗口。

iGC.Lite 可选择 `iGCBootstrapper.exe` 入口，程序会匹配实际的 iGC.Lite 窗口进程。Armoury Crate 的包应用入口尚无通用启动支持；Aura SDK 模式不需要打开它的界面。

## 录制、保存与调整等待

录制开始后会打开或恢复原厂软件。录制前把设备置于与目标相反的状态，并回到固定的起始页面。

1. 点击“录制开启”或“录制关闭”。每次录制从空序列开始，保存新序列会替换对应草稿；取消录制保留原序列。
2. 把鼠标移到需要点击的位置，按 F8。**F8 只记录坐标，不会帮你点击。** 然后手动点击该位置，等待页面稳定，再记录下一步。
3. 完成后点击“保存序列”。此时只是回到设置草稿，**还要点击设置页“保存”** 才会写入文件。
4. 保存后重新进入设置，确认开启和关闭的步数。回到相同起始页面，分别测试关闭、开启、关闭两次、开启两次。

录制只支持客户区内的单击，不记录键盘输入、拖动、按钮名称或状态。不要录制风扇转速、电压、超频、账号页面或会变动的文件列表。

每步默认等待 900 毫秒；录制过程中手动等待 5 秒并不会保存成 5 秒。慢页面可以在相应序列旁点“等待…”：

- 选择第 N 步，设置**该次点击后**的等待。如果第 N+1 步页面还没加载好，应增加第 N 步的等待。
- 点击“应用到草稿”，再保存设置；取消等待编辑不会更改草稿，取消设置页不会更改磁盘配置。
- 首次窗口已激活到第一次点击之间的等待，在“首次点击前等待”中调整，默认 1200 毫秒。
- 两种等待均允许 0～30000 毫秒；0 表示不额外等待。等待不是页面就绪检测，需要实测。

“清除”只移除相邻的开启或关闭草稿，保存前可取消撤销。无需修改 XML 或重录正常坐标来调整等待。

## 日常使用与停止

操作时保持与录制时相同的起始页面、布局和窗口大小，尽量保持相同屏幕缩放设置。不要在回放期间移动鼠标、切换窗口或遮挡目标；程序检查到窗口变化会停止。

主界面结果区可滚动、选中并复制。全部操作会按联力、TRYX、显卡、华硕依次执行，记录每项结果；一项失败通常不阻止其他项，点击“停止操作”则取消后续操作。批量操作停止时保留之前完成项目的结果；正在执行的一项可能已经部分生效。

托盘菜单也有“停止操作”。系统或厂商调用可能需要返回后才能响应取消。停止不撤销已生效步骤，不会自动重试；先确认当前页面和设备状态，再决定是否恢复。

勾选自动最小化后，成功回放会请求收起原厂窗口；如果“序列已执行，但未能自动最小化”，请手动收起，不要仅为收起窗口再次执行开关。中途失败会保留原厂窗口供检查。

## Aura SDK 的特殊行为

新配置默认选用 SDK，旧配置保留原有选择；旧文件没有 SDK 字段时继续使用录制。默认选用不代表 SDK 已安装或设备兼容。

- 关闭：向识别到的主板、ARGB、内存灯光写入黑色，并持有控制会话。结果会列出识别到的类别。
- 开启、退出或取消 SDK 选项：释放控制权，恢复原厂默认灯效。默认灯效本身设为关闭时，不会强制点亮。
- 不保证恢复动画的精确状态，也不保证其他 Aura 设备不受全局控制权切换影响。iGC.Lite 或其他灯控软件持续写入时可能冲突。
- SDK 失败不自动改为回放录制。若切换录制方式，已有录制会保留。
- SDK 最多等待 15 秒；超时或取消后停用本次会话，底层调用可能仍在执行。退出最多等待 3 秒释放，未确认时提示状态未知。退出后检查原厂灯效。

## 出现问题时

| 看到的情况 | 下一步 |
| --- | --- |
| EXE 无法启动，提示缺少 .NET Framework | 安装 Microsoft 的 .NET Framework 4.8 运行环境；不要把 .NET SDK 当作替代 |
| 提示已经运行 | 双击系统托盘图标，或按 Ctrl+Alt+F12；关闭主窗口不会退出 |
| 程序路径未配置或不存在 | 进入相应标签页重新选择原厂 EXE，确认能手动启动；已有录制仍保留 |
| 找不到窗口，或 Windows 错误码 | 先手动启动原厂软件，检查入口、安装完整性和权限；不要反复启动多个实例 |
| 原厂软件以管理员运行 | 从托盘退出控制台，右键 EXE 以管理员运行；仅在需要时使用该权限 |
| L-Connect / KANALI 托盘恢复失败 | 从原厂托盘手动打开，确认实际页面已显示，再重试。厂商版本变化可能使恢复入口失效 |
| F8 或全局快捷键注册失败 | 关闭或改掉占用该组合键的软件；主界面按钮仍可使用。F8 被占用时需重新开始录制 |
| 窗口失焦、被遮挡、点击偏移 | 确认没有后续点击，恢复录制时布局与起始页面；软件更新后重新校准 |
| 下一页还没加载就点击 | 增加前一步“点击后等待”；第一步太早则增加“首次点击前等待” |
| “尚未录制”或被跳过 | 录制并保存对应方向的序列。无需使用的组可以留空 |
| 重复开启反而关闭 | 原厂按钮可能是切换开关；尝试录制明确的开启/关闭入口。没有这样的入口时，不能把此录制当成幂等命令 |
| Aura 未注册、未识别设备 | 检查原厂 Aura 软件与服务；不要下载来历不明的 DLL。也可取消 SDK 并配置录制备用 |
| SDK 状态未知 | 停止重试，退出控制台并检查原厂灯效；后台线程超时不代表硬件调用已中断 |
| 恢复保护、保存被禁用 | 保留整个配置目录，用自己的有效备份恢复后重启；不要清空目录或覆盖重录 |
| 配置被其他程序修改 | 退出并重新读取，再确认草稿；不要在程序运行时手工编辑 XML |
| 新版本配置保护 | 使用写入该配置的对应版本；不要强行降低版本号来绕过保护 |

反馈时提供错误文字、发生步骤、软件版本、窗口处于未运行/最小化/托盘隐藏中的哪种状态，以及“复制脱敏诊断”的结果。诊断省略路径、用户名、设备标识和坐标；复制前的数字来自当前设置草稿，可能尚未保存。不要直接公开 `settings.xml`、配置备份、原厂日志或带私人内容的截图。

## 更新、备份与卸载

配置目录：在资源管理器地址栏输入 `%LOCALAPPDATA%\TangerineRigControl`。

- **备份**：从托盘退出后复制整个目录到自己选择的位置。正常保存只保留上一份 `.bak`，它不是长期版本历史；关键录制建议单独备份。
- **自动恢复**：主文件损坏时尝试有效 `.bak`。恢复后保存会另存故障原文件，保留好备份。两者都不可读时禁止保存，不表示录制已删除。
- **手动恢复**：先退出，另存现有目录，再把自己确认有效的备份复制为 `settings.xml`，重新启动核对步数。不要只凭文件大小判断备份有效。
- **更新**：退出、备份、替换程序，再核对步数。保持固定程序目录；如果移动了 EXE，需要重新保存登录启动选项，确保路径指向当前 EXE。
- **卸载**：先取消“Windows 登录时启动”并保存，从托盘退出，再删除程序文件夹。配置默认保留；确定不再需要且已备份后，可自行删除上述配置目录。

程序默认只写本地配置；启用登录启动时写当前用户的 HKCU Run，不创建系统服务或管理员计划任务。不含账户、遥测、云同步或自动更新请求；不控制原厂软件自己的网络行为。
