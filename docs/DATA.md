# 数据目录与升级保护

从 0.4.3-preview 开始，新默认根为 `%LOCALAPPDATA%\Tangerine`。应用身份、XML schema 1、设备路径和录制格式保持不变。

| 写入位置 | 用途 |
| --- | --- |
| `Apps/TangerineRigControl` | 新安装程序、卸载器、随包文档和对应源码 |
| `Data/TangerineRigControl/Config/settings.xml` | 本机偏好、原厂 EXE 路径和录制坐标 |
| `Data/TangerineRigControl/Backups` | 上一次 `settings.xml.bak` 及故障原件 `settings.xml.recovery-*` |
| `Data/TangerineRigControl/Runtime` | `.lifecycle.lock`、迁移来源 SHA-256 清单 `legacy-source.sha256`、发生中断时保留的 `migration-pending` |
| `Data/TangerineRigControl/Temp` | 原子保存时的临时 XML；成功或已捕获的失败后删除本次临时文件，异常断电可能留存 |

配置是未加密的本机文件；不会自动上传。没有数据库、浏览器内核 profile、应用日志、缓存、模型或云端数据，因此不建立空的 Storage、Logs、Cache。备份不是长期历史，每次正常保存只保留上一份。

## 入口及兼容例外

源码构建、Portable 和安装版使用相同数据位置，不按 EXE 所在目录另建配置。Portable 只表示程序免安装，不表示配置跟着 U 盘走。本工具没有配置路径命令行选项或环境变量；测试 `SettingsFile(path)` 使用显式隔离路径，不参与默认目录发现。用户已经选择的原厂 EXE 路径完整保留，不搬迁外部程序或其数据。

已登记的 `%LOCALAPPDATA%\Programs\TangerineRigControl` 和 `%LOCALAPPDATA%\Programs\Tangerine\TangerineRigControl` 在原位置升级。安装登记必须与卸载命令精确匹配。便携程序仍在用户解压位置运行。安装器不移动任何配置，也不自动启动程序。

以下写入位于集中目录之外，属于有意保留的边界。

- `%LOCALAPPDATA%\TangerineRigControl\.lifecycle.lock` 是兼容旧安装器/程序的独占锁；即使全新安装也会建立。应用和安装器按相同顺序获取旧锁与新 Runtime 锁，沿用原单实例互斥量。
- 旧 `%LOCALAPPDATA%\TangerineRigControl` 中的配置原件在复制后保留。没有搜索其他磁盘或其他用户配置，也不自动导入 EXE 旁的同名文件。
- 开始菜单、HKCU 卸载登记和用户主动启用的 HKCU Run 自启项由 Windows 管理。取消自启和卸载只删除精确指向当前安装的命令，不影响另一便携入口。
- NSIS 解压插件/卸载器会使用系统临时目录；Windows 的安全扫描、运行记录和共享 .NET Framework 不由应用管理。自检使用系统临时隔离目录，开发产物和测试日志留在工程忽略的 `artifacts/`。
- 用户选择的外部备份目录、原厂软件自己的日志/缓存不移动。本工具没有网页存储或浏览器 profile。

## 第一次读取旧配置

1. 从托盘退出所有版本。新程序获取锁后检查旧默认目录与新位置，拒绝目录联接、符号链接及未知文件。两代旧安装版和旧便携版原本使用同一旧默认数据目录，无须按 EXE 位置重复导入。
2. 只接纳 `settings.xml`、`settings.xml.bak` 和既有 `settings.xml.recovery-<32位标识>`。主配置及备份必须能按当前/旧 schema 校验；损坏、更新 schema、未完成保存或占用时停止。只有备份存在时可迁移，随后继续原有备份恢复流程。
3. 在 Runtime 下建立待处理目录，复制主配置到 Config、备份及故障原件到 Backups，逐份比对 SHA-256，再检查来源未变。提交目标目录和来源清单后清除待处理目录。原件始终保留，不改写 XML。
4. 后续启动及保存检查来源清单。旧文件被新增、修改或删除，新旧两处无凭据地同时存在，或残留待处理目录时都停止；不会选择“最新的一份”，不会自动合并或双写。

当前程序只写新位置。成功迁移后请持续使用新版，旧版不会认识新目录，仍可能读取旧快照。原有互斥量与双锁保护支持锁协议的版本；不能阻止用户在退出新版后另开旧版。旧版随后修改原件时，新版会明确拒绝继续，保留两边结果。早期无维护锁版本不能提供跨 Windows 会话互斥，不应与新版交替或并行运行。

## 中断、冲突与回退

出现保护提示时，先退出全部版本，分别备份旧目录和新 Data 目录，包括 Runtime 里的清单与待处理副本。不要仅删除 marker、清单或旧目录来绕过检查。

- **迁移中断**：原件未动，副本留在 `Runtime/migration-pending` 或已提交的 Config/Backups。核对原件、清单和副本后，若确定新版从未保存，可把整个新 Data 目录另存为独立恢复档，再由新版重新复制。不要覆盖旧原件。
- **迁移后旧版改写或出现两份配置**：分别保存两个目录，人工核对录制步数、设备路径和偏好，确定唯一权威版本后再恢复。程序不猜测哪个版本正确，也不提供自动合并。
- **需要回退旧程序**：保留新版 Data 目录及旧原件。旧版读取的是迁移前快照，新版保存不会同步回旧目录；如需采用新配置，先逐项确认兼容，再在全部程序退出后显式恢复，不能直接覆盖未备份的旧文件。重新升级仍须核对新旧冲突。
- **主文件损坏**：原有备份恢复保护继续有效。新位置使用 `Backups/settings.xml.bak`，恢复后保存将故障主文件另存至 Backups，不覆盖有效备份。两份都损坏时禁止保存。

卸载只删除清单内程序文件、精确归属的入口和登记，保留新旧配置、迁移记录、备份、用户额外文件以及共享父目录。重装后的首次运行继续检查这些数据。

本轮自动验证使用虚构目录和独立测试身份；用户真实配置未迁移。正式身份的托管机安装、干净 Windows、真实历史数据回退及实际硬件需按对应证据分别判断，源码自检不替代这些验收。
